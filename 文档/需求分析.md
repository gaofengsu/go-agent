# 需求分析

## 1. 项目背景

本项目 `go-agent` 是对现有 Python 教育型 "nano" 家族项目的 Go 语言重构与整合，核心参考以下三个子项目：

| 源项目 | 核心概念 | 代码规模 | 教育目标 |
|--------|----------|----------|----------|
| `nanoAgent/` | OpenAI Function Calling Agent | ~100-280 行/文件 | 构建可执行系统命令、读写文件的 Agent |
| `nanoMemory/` | Agent 记忆架构（9 级渐进） | ~80-210 行/文件 | 从状态机到生产级 SDK 的记忆管理 |
| `nanoSkills/` | Agent Skills 标准 | ~140 行 | 通过 YAML Frontmatter 实现专业化能力渐进披露 |

> **设计哲学继承**：保持 intentionally small（有意精简）、self-contained（自包含）、copy-paste runnable（复制粘贴即可运行）的教育风格，同时利用 Go 语言的静态类型、并发模型和编译时安全特性提升工程化水平。

## 2. 功能需求

### 2.1 Agent 核心引擎（源自 nanoAgent）

**FR-A1. 基础 Agent**
- 支持 OpenAI 兼容 API（OpenAI、StepFun、OpenRouter、Minimax 等）
- 实现 Function Calling 循环：`LLM 调用 → 工具执行 → 结果回传 → LLM 再调用`
- 内置基础工具集：`execute_bash`、`read_file`、`write_file`
- 最大迭代次数限制（默认 5 次），防止无限循环

**FR-A2. 增强 Agent（agent-plus）**
- **记忆注入**：基于 Markdown 文件的短期上下文记忆（最近 50 行）
- **任务规划（Planning）**：支持 `--plan` 模式，将复杂任务分解为 3-5 个可执行步骤
- **步骤执行**：逐步骤执行，前一步结果作为后一步上下文
- **错误处理**：工具执行异常捕获，不中断主循环

**FR-A3. ClaudeCode 风格 Agent（agent-claudecode）**
- **富工具集**：`read`（带行号）、`write`、`edit`（精确替换）、`glob`（文件查找）、`grep`（内容搜索）、`bash`、`plan`
- **规则系统（Rules）**：从 `.agent/rules/*.md` 加载项目级规则注入 System Prompt
- **技能系统（Skills）**：从 `.agent/skills/*.json` 加载技能描述
- **MCP 集成**：从 `.agent/mcp.json` 加载外部 MCP 工具定义
- **嵌套规划**：`plan` 工具支持在对话中动态分解任务

### 2.2 记忆系统（源自 nanoMemory）

采用 **渐进式 6 级架构**（从原 9 级中选取最具教育意义且适合 Go 实现的级别）：

| 级别 | 名称 | 核心机制 | Go 实现要点 |
|------|------|----------|-------------|
| L0 | 状态机 | 无记忆 | 基准对照 |
| L1 | 文件记忆 | JSONL + 关键词匹配 | 标准库 `bufio.Scanner` + `strings` |
| L2 | 向量记忆 | OpenAI Embedding + 余弦相似度 | `gonum` 或自实现向量运算 |
| L3 | 混合评分 | 相关性 × 时效性 × 重要性 + 反思 | 时间衰减公式 + 并发 LLM 评分 |
| L4 | 知识图谱 | SQLite SPO 三元组 + 时序追踪 | `database/sql` + `modernc.org/sqlite` |
| L5 | 摘要压缩 | LLM 压缩对话摘要 | 周期性合并机制 |

**FR-M1. 记忆操作统一接口**
- `Save(input, response)`：提取事实并持久化
- `Search(query)`：按级别定义的策略检索相关记忆
- `Extract(input, response)`：调用 LLM 提取关键事实/三元组/摘要

**FR-M2. 记忆事实提取**
- L1-L3：提取文本事实列表（JSON 数组）
- L4：提取结构化三元组 `(subject, predicate, object)`
- L5：生成单句摘要或 `NONE`

**FR-M3. 反思机制（L3）**
- 当记忆数量达到阈值时，触发 LLM 生成高层洞察
- 将洞察写入独立反思文件

**FR-M4. 知识图谱时序（L4）**
- 支持矛盾检测：新事实与旧事实冲突时，使旧三元组失效（`valid_until`）
- 支持历史查询：查看实体属性的时间线

### 2.3 Skills 系统（源自 nanoSkills）

**FR-S1. Skill 文件解析**
- 解析 YAML Frontmatter 格式：
  ```yaml
  ---
  name: git-expert
  description: Git advanced operations expert
  ---
  <skill body>
  ```
- 递归扫描目录下的所有 `SKILL.md` 文件

**FR-S2. 动态技能激活**
- 自动生成 `activate_skill` 工具，枚举值为所有可用 skill 名称
- Agent 可自主决定调用 `activate_skill(name)` 加载特定技能正文
- 激活后将 skill body 以 XML 格式注入对话上下文

**FR-S3. 技能目录切换**
- 支持 `--skills-dir` 参数指定技能目录
- 内置 `skills-real/`（真实专业能力）和 `skills-fake/`（模拟场景）两套示例

### 2.4 配置与运行环境

**FR-C1. 统一配置管理**
- 环境变量优先级最高：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`
- 支持 `minmax.json` 配置文件覆盖默认参数
- 支持 Minimax、OpenAI、StepFun 等多提供商配置

**FR-C2. CLI 接口**
- `go-agent run "task"`：基础运行
- `go-agent run --plan "task"`：启用任务规划
- `go-agent run --skills-dir ./skills-real "task"`：指定技能目录
- `go-agent memory --level 4`：指定记忆级别

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 目标 | 说明 |
|------|------|------|
| 编译时间 | < 5s | 单模块编译，无复杂依赖 |
| 冷启动 | < 100ms | 无解释器启动开销 |
| 记忆检索 | < 50ms (L1/L4) | 本地文件/SQLite 查询 |
| 记忆检索 | < 500ms (L2/L3) | 含 Embedding API 调用 |
| 工具执行 | < 30s | bash 命令超时限制 |

### 3.2 可维护性需求

- **静态类型安全**：利用 Go 类型系统避免 Python 的动态类型运行时错误
- **显式错误处理**：所有可能失败的操作返回 `error`，不 panic
- **接口抽象**：Agent、Memory、Skill 三大核心定义 `interface`，实现可替换
- **单文件可运行**：每个 Level/Agent 变体保持为单文件或最小依赖，保持教育性

### 3.3 可测试性需求

- **无网络测试**：通过接口注入 Mock LLM Client，所有核心逻辑可离线测试
- **临时存储**：测试使用 `os.MkdirTemp` 隔离文件/SQLite 状态
- **覆盖率目标**：核心逻辑 > 80%

### 3.4 可移植性需求

- **单二进制部署**：`go build` 产出单文件可执行程序
- **跨平台**：Linux/macOS/Windows 均支持（工具执行使用平台适配）
- **零外部运行时依赖**：仅依赖 Go 标准库 + 少量纯 Go 第三方库

## 4. 约束与假设

### 4.1 约束

1. **LLM 依赖**：必须提供 OpenAI 兼容的 API Key 才能运行（Embedding、Chat、JSON Mode）
2. **沙箱缺失**：`execute_bash` 等工具直接执行系统命令，不适用于不可信输入
3. **Go 生态差异**：Go 没有 Python `openai` 库的官方 SDK，需使用社区库（如 `sashabaranov/go-openai`）或自研 HTTP 客户端
4. **无泛型过度使用**：为保持代码可读性，尽量避免过度复杂的泛型

### 4.2 假设

1. 用户具备 Go 1.21+ 环境
2. 用户已配置有效的 LLM API Key
3. 运行环境具有文件系统读写权限和网络访问权限
4. 教育目的优先于生产级鲁棒性（与 Python 原版保持一致定位）

## 5. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Go OpenAI SDK 功能差异 | 高 | 优先选择 `sashabaranov/go-openai`，已验证支持 Tools/Streaming |
| SQLite CGO 跨平台编译 | 中 | 使用 `modernc.org/sqlite` 纯 Go 实现 |
| Embedding 向量运算性能 | 低 | 维度固定（1536/3072），Go 纯计算足够 |
| 记忆文件格式兼容性 | 低 | 不追求与 Python 版文件互读，独立存储 |
